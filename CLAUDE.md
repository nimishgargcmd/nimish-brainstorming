# Multitasking execution FY27

## What This Is
FY27 redesign of the Mobile Teams Meeting Multitasking IA prototype. Forked from `../../personal work projects/Mobile Teams Meeting Multitasking IA/` to explore a new visual language without disturbing the original code.

The original prototype remains the reference for IA, navigation persistence, and behavior. This copy is the playground for a fresh visual direction (typography, color, surface treatment, motion) on top of the same underlying app logic.

## Intent
- **Keep:** information architecture, panel navigation, ActiveMeetingContext pattern, notification/recording/mic behavior, multitasking dock model.
- **Reinvent:** visual language — type ramp, palette, elevation/surface, iconography choices, motion grammar, density.
- **Don't touch yet:** hosting. No Vercel, no Azure Static Web Apps. Local dev only until the redesign is ready to show.

## Stack (inherited from source)
- Vite 6.3 + React 18 + TypeScript
- Tailwind CSS 4.1 via `@tailwindcss/vite`
- Radix UI primitives, Motion (Framer Motion) for animations
- React Router 7 (SPA, hash routing)

## Key Decisions (inherited — preserve unless explicitly redesigning)
- Self-hosted SF Pro font with @font-face alias system for Figma exports
- `viewport-fit=cover` added via JS at runtime, NOT in static meta tag
- Azure OpenAI for Copilot panel
- Figma asset imports use `figma:asset/...` prefix, resolved by vite plugin
- **Navigation persistence pattern:** `ActiveMeetingContext` (in `RootLayout`) is the source of truth for ALL state that must survive `MeetingPage` unmount/remount cycles (mic, video, recording, notifications, lobby count, agenda timer, `seenNotificationTypesRef`). Never use local `MeetingPage` state for anything that should persist when the user backgrounds and returns.
- **Recording indicator:** shown in the meeting header (top bar title row) and meeting dock (title row). NOT in the notification pill. Driven by `isRecording` from context.
- **Notification badge:** always-visible bell icon; badge appears when `notificationCount > 0`; badge resets to 0 when the notification hub is opened (Teams desktop behavior — opening the hub acknowledges all items). Counter increments once per unique icon type via `seenNotificationTypesRef` deduplication guard. Badge does NOT increment while the hub is open (`isNotificationHubOpenRef` ref pattern in `MeetingPage`).
- **Canonical mic icon components:** `MicOnIcon.tsx` / `MicOffIcon.tsx` for the bare icon; `MicOnIndicator.tsx` / `MicOffIndicator.tsx` for the background-pill variants. Use these everywhere — do not inline SVG for mic icons.
- **On-the-go mode header:** `alwaysVisible` prop on `MeetingHeader` keeps the header permanently shown (no auto-hide) when `currentView === 0`.
- **ParticipantsPanel actions menu:** participant/meeting actions live in an L2 "Options" panel triggered by the `...` button. Uses `MultitaskingPanel` with `isNestedView={true}`.
- **L2 back chevron standard:** all nested views use `MultitaskingPanel` with `isNestedView={true}`, which renders the `p3dc95180` left-chevron at `px-4` — same position as the ParticipantsPanel main header back button.
- **Segmented agenda timer:** the AIL timer (`AdditionalInfoLayer.tsx` → `SegmentedTimerPill`) renders one segment per agenda item, each segment's width proportional to its share of total meeting time (`flex-grow: duration`). Track `#1a1a1a` (running) / `#3f3a3a` (paused), fill `#584BDF`. Completed segments full, current shows live progress, future empty. No inline countdown text; the pause glyph overlays the in-progress segment. Has an `aria-label` (topic + minutes left) since it's an unlabeled-by-default button.
- **Agenda items live in context (editable):** `ActiveMeetingContext` holds `agendaItems` + `setAgendaItems` (seeded from `INITIAL_AGENDA_ITEMS`) so edits survive backgrounding. Timer math is **index/epoch-based**, so `id` is a display key only and edits are restricted to keep the started prefix `[0..currentTopicIndex]` immutable. Editor = `AgendaEditView.tsx`, reached via the Agenda panel header **Edit** button (nested `isNestedView`). Edits **buffer locally and commit on Save**; Cancel/back discards via an iOS-style `AlertDialog`. Editable scope: not-started items (reorder ↑/↓ chevrons, duration stepper, title textarea) + the **in-progress item's duration only** (stepper min clamped to elapsed time). `PillActionButton.tsx` is the shared full-width pill (Pause / Reset / Add agenda item).
- **Immersive mode (drag-to-maximize panel):** `ImmersiveSplitContext` provides `{ isImmersive, dragHeight, isDragging }` to every `MultitaskingPanel` (incl. nested views) — the detent height is a shared component concern, not per-panel props. `MeetingPage` owns the pointer-drag/snap and `isImmersive` (resets per panel via a `[activePanel]` effect), and renders `PanelResizeHandle` (Fluent reorder-dots grip) **on the divider seam** between stage and panel. Two detents only: default 65vh ↔ immersive `calc(100dvh - IMMERSIVE_OFFSET_PX)` — snap on release, tap toggles. In immersive the header/AIL swap for `ImmersiveMeetingBar` (black bg, red call-end handset icon — no circle — pinned to **48px** so the panel's bottom divider clears the bottom bar) and the stage collapses. `IMMERSIVE_OFFSET_PX` (in `ImmersiveSplitContext`) = status bar 59 + strip 48 + handle 10; keep it in sync if those heights change. Drag hit area = the thin divider ∪ a 44×44 square centered on the dots. The immersive bar also carries a back chevron (`Header.tsx` `p4dacf00` glyph) wired to `handleBack`.
- **DM / 1:1 chat surface:** tapping any Chat-list row opens `dm/:conversationId` (sibling route, no bottom nav — `DMChatPage` reproduces the AppShell grey/white dock layering). Light `chat/ChatThread` thread reuses the meeting chat's logic via the shared `useChatSend` hook + the same `/api/openai` endpoint (`sendDMMessage` 1:1 prompt; meeting uses `sendChatMessage`). **Row #7 "Marketing Team Sync" shares the LIVE in-meeting thread** — the meeting chat state was lifted into `ActiveMeetingContext` (`chatMessages`/`setChatMessages`, seeded from `meetingChatSeed.ts`). Other rows are seeded `DM_THREADS` (`lib/dmData.ts`); group rows (`members[]`) reply as a random member. The DM reuses the meeting's `NativeInputBar`/`CollapsedInputBox` (new light `theme`) **inline** so the thread flex-shrinks above the on-screen keyboard (native keyboard suppressed); tapping the thread dismisses it; it auto-scrolls to the latest timestamp. Reaction emoji render handles both image assets and Unicode glyphs (e.g. 🔥).
- **Dock carry-over across surfaces (no jitter):** each surface mounts its own `DockUIProvider` + `MeetingDock`, so the dock's state is carried between them via module-level `lib/dockPersist.ts` (`lastDockState`). `DockUIProvider` accepts `initialSurfaceDefault`/`initialManualState` and `DMChatPage` seeds them **synchronously** (read `getLastDockState()` in render) so the first paint is already correct — no flash. `MeetingDock` skips its slide-in **entrance** animation when carried across surfaces (`dockHasEnteredSession` flag; reset on return-to-meeting / end-call) and the inner expanded-content `motion.div` uses **`initial={false}`** so a fresh mount paints at its target height instead of flashing the tiles full-height then collapsing (that flash was what jittered the white foreground on Chat → DM). The DM thread does **not** wire `useDockScroll` (a bottom-anchored chat would feed spurious scroll reports); the dock there follows carried state + header drag + keyboard only. Keyboard-open collapses the dock; closing it never re-expands.
- **Chat / Activity list rows:** two-column layout (Figma `879:26367`) so the subtitle truncates **before** the timestamp (left `flex-1` column holds name + preview; right `shrink-0` column holds time). Subtitle = the **live last message** of the associated DM thread (`mkt` mirrors the in-meeting chat). Presence dot is `#21A366` to match the DM header indicator. Recipient avatars use clean Fluent faces from `src/assets/figma/dm/avatars/` — the older chat-frame PNGs (ray/beth/daisy) bake in a green presence dot that looked wrong on bubble avatars.
- **Favicon + iOS home-screen tile:** authentic Teams glyph (Figma `918-26139`, 180px) rasterised to PNGs in `public/` — `favicon-{16,32}.png` (browser tab) + `apple-touch-icon.png` (180, **opaque full-bleed**, no transparent corners — iOS fills transparency black and applies its own mask) + `public/icons/icon-{192,512}.png` (manifest). iOS caches the tile at add-to-home-screen time, so testing needs delete-and-readd, and a self-signed dev cert can block the icon fetcher (use the Azure valid cert).
- **Presentation pointer cue (feature-flagged OFF):** `PresentationPointer.tsx` is mounted in `App.tsx` but `POINTER_ENABLED = false` → renders null and attaches no listeners. Inert until the flag is flipped. Merged from `main` (`dd41bd5`); independent of the DM/dock work.

## FY27 MVP Redesign (version-gated — Final Vision must stay untouched)
The live version switcher (`useVersion()` → `activeVersionId === "current"` = FY27 MVP, else "Final Vision"). **Every MVP change is gated by `const isFy27Mvp = isMvpFamily(activeVersionId);`** (`isMvpFamily` from `@/app/versioning/versions`) and the existing JSX stays as the FV `else`/fallback. Shared components branch internally; never alter the FV path.

### Version family — FY27 MVP + MVP checkpoint (`isMvpFamily`)
There are now **three versions** (`src/app/versioning/versions.ts`): `final-vision` (baseline), `current` (FY27 MVP, `basedOn` baseline), and **`mvp-checkpoint`** ("MVP checkpoint", `basedOn: "current"`). The checkpoint **inherits the entire FY27 MVP** and diverges **only in the meeting stage**.
- **Inline MVP gates use `isMvpFamily(activeVersionId)`, NOT `=== "current"`.** `isMvpFamily(id)` is true for both `current` and `mvp-checkpoint`, so every `isFy27Mvp`/`isMvp` flag (panels, UFD, toast, self-tile, RTT, pre-join, calendar, etc.) treats the checkpoint identically to FY27 MVP. Never reintroduce a raw `activeVersionId === "current"` inline gate — it would collapse the checkpoint to Final Vision.
- **The stage divergence is a SLOT, not an inline gate.** The meeting stage is the **`MeetingViews` slot** (`register.ts`; baseline → `SwipeableViews`, `current` → `MeetingViewsGallery`). To change only the stage for the checkpoint, `registerComponent("MeetingViews", "mvp-checkpoint", <NewStage>)`. Until that's registered, the checkpoint falls back along `basedOn` to `current`'s `MeetingViewsGallery`, so it renders **identical to FY27 MVP**.
- **Checkpoint-only branch point:** use `activeVersionId === "mvp-checkpoint"` (or a dedicated slot registration) **only** for the stage redesign; everything else must stay behind `isMvpFamily`.
- **Branch:** the MVP checkpoint work started on the **`mvp-checkpoint`** git branch (forked from `mvp1`). As of **2026-07-02** the stage redesign shipped — `mvp-checkpoint` was fast-forwarded into `main` (and `mvp1`) and deployed to Azure. Default selection remains **Final Vision**; the checkpoint is opt-in via the switcher.
